# PitchMi — STATUS

## Current state
v1 core loop is built end-to-end (T-1150), now a **zero-edit flow** (T-1169): record take 1 → transcribe (ElevenLabs Scribe) → subtitles built straight from the surviving words' REAL timestamps (fillers stripped, no LLM rewrite, no re-pacing) → karaoke re-record guided by those subtitles → evaluate → results. No transcript editor, no speed slider, no path/pacing engine — to change wording or pace the user just records again. **Server** (Express) exposes projects, transcribe (folds in subtitle building), evaluate (timing/accuracy scoring + Gemini delivery eval via OpenRouter/Gemini), save, takes, ad stub, and admin — behind a fail-open kill switch, surge auto-trip, upload cap, JWT auth (Supabase JWKS ES256 with HS256 fallback), and RLS. **Client** (Next.js 15) implements the screens (editor removed) with anonymous Supabase auth, camera recorder, `performance.now()`-based karaoke teleprompter, results (Try again / New video / OS Share — no cloud save, so my-videos is unlinked), and admin. All automated acceptance checks pass. Not yet run: real external-API smoke (needs keys) and the manual browser checklist below.

- **Known issue (T-1172):** event rows written **before** this change carry no `scores.cost`, so an admin date range spanning the deploy shows `total_stt_usd`/`total_eval_usd` of `$0.0000` for the older days while `total_cost_usd` still sums them correctly. Expected, not a bug; the split becomes complete once every row in the range is post-deploy. Historical `cost_usd` figures are also still at the old (75% overstated) $0.007/min Scribe rate — they are not back-corrected.
- **Deviation (T-1172):** the 30s cap is enforced with a **3s tolerance** (`TAKE_TOLERANCE_S`), i.e. the server rejects only above 33s. This is not grace for the user — the client still hard-stops at 30.000s — it absorbs container rounding and `MediaRecorder`'s imprecise stop, which routinely lands a "30s" take at 30.4s. Rejecting at exactly 30 would 413 legitimate takes.
- **Deviation (T-1172):** the "Time's up" interstitial is a judgment call layered on top of "hard stop, no grace" — it does not extend recording by a millisecond, it only refuses to silently transcribe a severed take 1 into `projects.path`. If it isn't wanted, deleting the `cutOffBlob` block in `recorder/page.tsx` is a two-line revert and nothing else in T-1172 depends on it.
- **Deviation (T-1172):** admin aggregate money columns now render at **4 decimals** (was 2 for Cost). A real day costs single-cent money, so `toFixed(2)` rendered every split as `$0.00` and made the new columns useless.
- **Deviation (T-1170):** "My videos" is **unlinked, not deleted**. With Save-to-cloud gone from results nothing writes to Storage, so the entry point would be a dead end — the home nav link is removed. The `/videos` screen, `POST /api/save`, `GET /api/takes/:id/url`, the `saved_takes` table and the private `videos` bucket all remain functional and tested (`api.save.test.js` green); v2's feed/publish will reintroduce saving and re-link the screen. `lib/strings.ts` still exports `savedToast`/`myVideosLabel`/`savedButton` (now unused by results) for the same reason — dormant, not dead.
- **Deviation (T-1169):** schema left untouched but two columns are now intentionally unused — `projects.speed` (the global speed slider is gone) and `projects.original_words` (only `/api/path` read it). Neither is dropped; transcribe simply stops writing them. `projects.script` is still written (filler-stripped transcript, reference only). The client `Project.speed` type field is kept because the DB row still returns it.
- **Deviation (T-1168):** the task specced "apply the effRate basis to the ±35% smoothing band" as a single symmetric basis. Implemented asymmetric instead — fast bound on `voicedRate`, slow bound on `effRate`. A symmetric effRate-centred band raises the *fast* floor above the real articulation rate, so every anchored word pinned to its (faster) take-1 timestamp would be stretched off its beat — directly breaking the "light edits keep original beats" promise (T-1167). Asymmetric keeps that promise while still letting effRate-paced inserted runs survive smoothing. Verified: high-coverage anchors keep exact take-1 timestamps in `path.pacing.test`.
- **Root cause + fix (T-1161, P0 evaluate transport):** *Current behavior* — on iPhone iOS Safari the evaluate `OPTIONS` preflight returned 204 but the `POST /api/evaluate` never reached the server (nothing logged), while the wait screen advanced clock-driven labels to "Scoring your delivery" and hung forever. The same take transcribed fine seconds earlier. *Reproduction* — desktop Chrome could not reproduce (fetch and XHR both work there); the failure is iOS-Safari-specific and was observed on-device. *Root cause* — the only thing that changed between the working transcribe path (fetch) and the broken evaluate path was T-1160's rewrite of `evaluateVideo` to `XMLHttpRequest` with `xhr.timeout = 5min` + `xhr.upload` progress on a cross-origin request. After the CORS preflight succeeded WebKit never dispatched the actual POST body, and crucially **none** of the XHR handlers (`onload/onerror/ontimeout/onabort`) fired — so the promise never settled and the timer-driven labels kept lying about progress. *Chosen fix* — revert `evaluateVideo` to the identical `fetch` transport `transcribeVideo` uses, with an `AbortController` enforcing `EVAL_TIMEOUT_MS`; drop byte-level upload % (reliability > nice-to-have); replace the timer-driven labels with a state-driven 2-stage machine (`lib/evalStages.ts`) so any resolve→results / reject→error-screen outcome is honest and no post-response label ("Scoring") can appear before a server response. See `client/src/lib/__tests__/evaluate.test.ts` (success/network-error/timeout) and `evalStages.test.ts`.
- **Deviation (T-1160):** evaluate stage timings ride inside the existing `events.scores` jsonb under a `timings` key (not new columns) to honor "do not touch DB schema". Aggregates only read `scores.overall`, so they're unaffected; values are numeric metadata only.
- **Note (T-1161):** recorder + karaoke are now full-screen previews (`fixed inset-0`); their bottom-anchored Stop buttons use `.safe-pos-4` to clear the iOS home indicator (supersedes the T-1160 note that the recorder had no anchored CTA).
- **Deviation:** `jose` pinned to 5.x (not 6.x). v6 is ESM-only; the server is CommonJS and the Jest runtime can't `requireActual` an ESM-only module. v5 ships dual CJS/ESM. `jose` was not a pre-pinned library.
- **Deviation:** `multer` pinned to 2.x (not 1.x) — 1.x has published CVEs; multer was not a pinned library. API compatible.
- **Deviation:** added `original_words jsonb` column to `projects` (beyond §4). `/api/path` needs take-1 word timings and §4's schema had nowhere to persist them. Reflected in `server/db/migrations/0001_init.sql`.
- **Deviation:** local Node is v24.11.1; spec pins Node 22 (Railway runtime). v24 is backward-compatible for dev; `engines` allows `>=22`.
- **Deviation:** client `next@15.1.0` (nearest 15.x); all other versions as pinned.
- **Resolved (T-1162):** OpenRouter base64-video 500s are fixed by pinning provider routing to `google-vertex` with `allow_fallbacks:false` (AI-Studio, the failing backend, accepts YouTube URLs only). The `video_url` snake_case data-URL content part is confirmed correct against live OpenRouter docs; real per-take mime is used. The direct-Gemini `inline_data` fallback (`EVAL_PROVIDER=gemini`) remains available but is no longer the reliable path.
- **Deviation (T-1163):** added `@playwright/test` (resolved 1.61.x) as a client devDependency for the RTL layout proof (`npm run test:layout`); chromium installed via `npx playwright install chromium`. Playwright was not a pre-pinned library — it runs a real browser, which jsdom/vitest cannot, and is the acceptance gate the spec required. A dev-only route `client/src/app/dev/prompter-layout/[fixture]/page.tsx` renders the real Prompter for the test; it is not linked from the product UI.
- **Gap:** admin Service tab toggle is optimistic (no GET service-state endpoint in the fixed API list) and the "surge trip < 24h" alert banner is not yet wired. Minor; logs already record `surge_trip` events.
